# Contributing

This is a portfolio project rather than a product, but it is set up so that a
change can be made and verified without guesswork.

## Getting set up

```bash
git clone https://github.com/madhavthesiya/resumable-file-transfer
cd resumable-file-transfer
make            # builds all four implementations
make test       # generates the corpus, runs every suite
```

You need a C11 compiler and Python 3. Nothing else. The test corpus is
generated by `tools/make_dataset.py` and is deterministic — file contents are
seeded on the file's own path — so the same corpus appears on every machine and
CRC values are stable.

## Before opening a pull request

```bash
make check      # test + sanitizers + fuzz: what CI runs
```

That is: 366 checks, ASan/UBSan/TSan over the unit tests and an end-to-end
transfer, and the protocol fuzzer. CI additionally builds the clients on macOS,
which is the only thing that genuinely exercises the `MSG_NOSIGNAL` fallback.

## House style

The existing code has a shape; match it rather than the conventions of
whatever you usually write.

- **C11, and warnings are errors.** Every Makefile uses
  `-Wall -Wextra -Werror`. A warning is a build failure, which is deliberate.
- **Comments explain *why*, not *what*.** `i++ /* increment i */` adds nothing.
  `/* clamp against sent_*, not ack_*, because ... */` is the kind that earns
  its line. Where a decision had a real alternative, say which and why.
- **No new socket calls outside `src/common/netutil.c`,** and no `send`/`recv`
  outside `src/common/protocol.c`. Both exist so that partial transfers and
  socket options cannot drift between the eight executables.
- **Keep the four implementations diffable.** `src/restart/server.c` should
  remain readable as `src/baseline/server.c` plus fault injection. That
  property is the main thing that makes the project teachable, and it is easy
  to destroy by refactoring one of them in isolation.

## Where things live

| | |
|---|---|
| `src/common/` | protocol, sockets, CRC-32, topic table, fault injection |
| `src/baseline/` → `restart/` → `resume/` → `parallel/` | each adds one idea to the previous |
| `tests/` | `test_common.c` for units, one `.sh` suite per implementation |
| `fuzz/` | decoder fuzzer, standalone and libFuzzer |
| `bench/` | benchmark harness, summariser, plots |
| `docs/` | architecture, protocol, benchmarks, findings, security |

## Changing the wire format

Update [docs/PROTOCOL.md](docs/PROTOCOL.md) in the same commit. The spec is
meant to be sufficient to write an interoperating client from, and a spec that
has drifted from the code is worse than none.

## Changing a benchmark

Results in [docs/BENCHMARKS.md](docs/BENCHMARKS.md) carry a mean and a standard
deviation over repeats, because a single run of this system can be 3× off — see
[docs/FINDINGS.md](docs/FINDINGS.md). Please do not add a single-sample number
to that document; add repeats, and report the spread.

## Reporting a bug

A reproduction is worth more than a description. For a decoder crash, the
fuzzer prints its seed and replays from `FUZZ_SEED=<n>` — attaching that is the
fastest possible bug report.
